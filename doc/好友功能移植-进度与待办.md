## 一、已完成的调查（结论基于本机真实 jar 反编译，非推测）

**实测用到的文件**（注意：recon 文档里写的 `D:\Minecraft\` 路径不存在）：

| 用途 | 实际路径 |
| --- | --- |
| 客户端 | `D:\temp\github\authlib-injector-mcyas\tmp\26.3.jar`（用户复制进来） |
| authlib 10.0.77 | `D:\Softwares\mc\.minecraft\libraries\com\mojang\authlib\10.0.77\authlib-10.0.77.jar` |
| authlib 4.0.43 / 6.0.54 | 同上目录，用于低版本兼容性验证 |
| javap | `D:\Softwares\jdk-11.0.18+10\bin\javap.exe` |

### 核心结论

1. **客户端 jar 里 `com/mojang/authlib` 条目数为 0** —— 好友网络层全在外部 authlib jar 中，recon 文档此点正确。
2. **好友端点无需新的门面转发代码**。本仓库已有 `DiscoveryFilter`（硬编码并逐条改写 discovery JSON）+ `DefaultURLRedirector`（`api.minecraftservices.com` → `<apiRoot>/minecraftservices`），`/friends`、`/presence` 已经被本地 httpd 兜底反向代理到认证服务器。
3. **唯一门面阻断点是 `AntiFeaturesFilter` 本地拦截 `GET /player/attributes`** 并返回不含 `friendsPreferences` 的 JSON → 客户端 `friendsEnabled()` 为 false → 好友入口不出现。**已改**（见下）。
4. **`Retry-After` 是服务端控制客户端轮询节奏的唯一手段**（`getFriendsPollInterval()` / `getPresencePollInterval()` 仅由响应头驱动）。recon 文档完全漏掉此点。
5. **HTTP 状态码映射**（反编译确认，精确）：`429`→TOO_MANY_REQUESTS，`>=500`→SERVICE_NOT_AVAILABLE，`403`→FORBIDDEN，`400`→UNKNOWN_PROFILE，`401`→UNAUTHORIZED，其它→ERROR。
6. **`updateAttributes` 是 POST 不是 PUT**（recon 文档写错）。
7. **客户端本地 10 秒冷却 + single-flight**；`PUT /friends` 成功后会清空客户端自存的 friends ETag。

### 低版本兼容性（已验证，结论：服务端无需任何适配）

- authlib **4.0.43**（1.16 时代）与 **6.0.54** 均**不含** `com.mojang.authlib.services` 包与 `FriendsService`。
- 旧版 `EnvironmentParser` 用 `minecraft.api.auth.host` / `account.host` / `session.host` / `services.host` 这套按服务分列的属性，**无** discovery 机制、**无** `PROP_DISCOVERY_HOST`。
- 故：**旧版本客户端根本不会请求好友接口**，实现它们是"死代码"，不影响旧版流程，也无需按版本分叉或加开关。

## 三、服务端待实现（另一仓库，非本仓库）

接口共 5 个，全在 `/minecraftservices/` 前缀下，均带 `Authorization: Bearer {accessToken}`：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/minecraftservices/friends` | 查好友列表（`If-None-Match` / `ETag` / `304`） |
| PUT | `/minecraftservices/friends` | 增删好友、接受/拒绝/撤回（靠 `updateType` 与标识字段区分四种语义） |
| POST | `/minecraftservices/presence` | 上报自身状态 + 拉取好友状态 |
| GET | `/minecraftservices/player/attributes` | **决定好友入口是否显示**，必须含 `friendsPreferences` |
| POST | `/minecraftservices/player/attributes` | 好友设置开关（**注意是 POST**） |

实现要点：
- `profileId` 是**带连字符**的标准 UUID（非「无符号 UUID」）。
- 应始终返回合理的 `Retry-After`。
- 状态码须精确（见上文第 5 点），否则客户端 UI 报错误提示。
- `GET /player/attributes` 必须返回完整属性（`privileges`、`profanityFilterPreferences` 等），因为门面已不再本地兜底。

## 四、服务端模块落点（已与用户讨论定型）

用户的认证服务器是多子模块 Maven/Gradle 工程，依赖分层：

```
第 0 层：common, communication
第 1 层：datasource → common；i18n → common；web-ui → common, i18n
第 2 层：schedule → datasource, communication
        security → common, communication, datasource, i18n
        yggdrasil → common, communication, security, i18n（+ datasource 仅传递）
第 3 层：api → common, communication, datasource, security, schedule
第 4 层：app → 上方全部；cli → common, communication（弃用）
```

用户确认的前提：
- **token 由 `security` 模块统一管理**，所有 web 功能模块都依赖它。
- **`api` 主要为 web 功能负责**，`yggdrasil` 同样自带其对应端点；**接口按功能内聚**。
- **`datasource` 用 mybatis-flex 提供基础服务**（数据库连接 + 基础 CRUD）。

### 定型结论：新建 `friends` 子模块，落在第 3 层

```
第 3 层
  friends → security, datasource, yggdrasil(仅角色解析), common, communication, i18n
```

**不写进 `yggdrasil`**：yggdrasil 是第 2 层被依赖者，塞入好友业务会让层次倒置。
**不进 `api`**：接口按功能内聚，friends 自带 controller，由 `app` 挂载。

模块内三块：
1. **好友关系（持久，走 mybatis-flex）**：两张表 + Mapper + service
   - 好友边 `(owner_id, friend_id, created_at)`，唯一索引 `(owner_id, friend_id)`；建议存**双向两条边**。
   - 好友请求 `(from_id, to_id, created_at)`，唯一索引 `(from_id, to_id)`；`where to_id = me` → incoming，`where from_id = me` → outgoing。
   - ⚠️ `ADD + profileId` 既表示"接受收到的请求"又表示"按 UUID 加好友"，需靠**请求表中是否已有对方发给我的记录**区分——这是最易写错处，建议抽独立方法。
2. **在线状态（内存，不走 datasource）**：进程内 `Map<uuid, (status, timestamp)>` + TTL。
   - 理由：presence 是短过期、高频写、低一致性要求的临时状态；mybatis-flex 基础 CRUD 扛不了每秒级写，也不该在 CRUD 层上叠 TTL 清理。重启丢失无妨，客户端会重新上报。
3. **对外协商层**：controller 处理 3 个 friends 端点。
   - DTO 字段名须逐字匹配契约；`profileId` 输出带连字符。
   - **建议 friends 自建 DTO**，不复用 yggdrasil 的角色 DTO（字段形状不同，混用会埋坑）。
