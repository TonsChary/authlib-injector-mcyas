# 好友功能技术规范

## 概述

本文规定第三方 Yggdrasil 服务端为了支持 Minecraft 官方「好友功能」（Friends）所必须实现的接口。

好友功能仅在较新的 Minecraft 版本（authlib 10 及以上，即 26.3 及以后）中存在。旧版本客户端不会请求本文所述的任何接口，因此实现本文接口不会影响旧版本客户端的兼容性，详见 [§版本兼容性](#版本兼容性)。

本文以 authlib 10.0.77 / Minecraft 26.3 为基准，通过反编译实际类文件得到，非推测。

## 基本约定

字符编码、请求与响应格式、错误信息格式均遵循 [Yggdrasil 服务端技术规范 §基本约定](Yggdrasil-服务端技术规范.md#基本约定)。

补充约定：

* 所有请求都带有 `Authorization: Bearer {accessToken}` 头部，其值为该玩家的 accessToken（即 Yggdrasil 登录流程颁发的令牌）。服务端应据此识别请求的发起者；令牌无效时返回 `401`。
* 所有请求与响应的 `Content-Type` 均为 `application/json; charset=utf-8`。
* 请求体与响应体的字段名由 Gson 反序列化（record 字段名），**区分大小写**，不得改动。

### 路径前缀

本文所有接口均位于 `<apiRoot>/minecraftservices/` 之下。这与 [Yggdrasil 服务端技术规范 §功能选项](Yggdrasil-服务端技术规范.md#功能选项) 中 `feature.enable_profile_key` 所述的 `POST /minecraftservices/player/certificates` 前缀一致。

### 轮询与缓存控制

客户端采用**轮询**方式获取好友列表与在线状态。服务端通过响应头 `Retry-After`（单位为秒）控制客户端的轮询间隔。

> **重要：** `Retry-After` 是服务端控制轮询节奏的**唯一**手段。若响应中不含 `Retry-After`，客户端将沿用上一次的值；若从未下发过，则使用客户端内置的默认间隔。**服务端应始终返回一个合理的 `Retry-After`**，否则客户端会以默认频率持续请求。

客户端自身的行为（服务端无需实现，仅供理解）：

* 每次成功请求后，客户端会在本地施加 10 秒冷却，冷却期内不发起新请求。
* 客户端对好友列表请求做了「单飞（single-flight）」处理：同一时刻只允许一个请求在途，其余调用直接复用缓存。
* 服务端返回 `304 Not Modified` 时，客户端沿用本地缓存。

### ETag 与条件请求

好友列表与在线状态两接口支持条件请求：

* 响应中若含 `ETag`，客户端会在下次请求时以 `If-None-Match` 头部带回。
* 若资源未变化，服务端应返回 `304 Not Modified`（无响应体）。
* 客户端的 `PUT /minecraftservices/friends` 成功后**会清空自身保存的好友列表 ETag**，因此随后的 `GET` 必定是完整的 `200`。

## 数据结构

### FriendDto

表示一个好友或一条好友请求中的对方角色。

```javascript
{
	"profileId":"对方的角色 UUID（带连字符的标准 UUID 格式）",
	"name":"对方的角色名称"
}
```

> 注意：这里的 `profileId` 是**带连字符**的标准 UUID 字符串（如 `069a79f4-44e9-4726-a5be-fca90e38aaf5`），与 Yggdrasil 主体规范中「无符号 UUID」的约定不同。客户端以 `java.util.UUID` 反序列化该字段。

### FriendsListResponse

```javascript
{
	"friends":[ /* FriendDto 数组，已互为好友的角色 */ ],
	"incomingRequests":[ /* FriendDto 数组，收到的好友请求 */ ],
	"outgoingRequests":[ /* FriendDto 数组，发出的好友请求 */ ]
}
```

三个字段均允许为 `null`，客户端会将其视为空数组。

### PresenceDto

表示一个角色的在线状态。

```javascript
{
	"profileId":"角色 UUID（带连字符）",
	"pmid":"角色 UUID（带连字符）",
	"status":"在线状态（见下表）",
	"lastUpdated":"状态最后一次更新的时间（ISO-8601 瞬时时刻，如 2026-01-01T00:00:00Z）"
}
```

`status` 的取值范围（`PresenceStatus` 枚举）：

|值|含义|
|--|----|
|`ONLINE`|在线|
|`PLAYING_OFFLINE`|在单人世界中|
|`PLAYING_REALMS`|在 Realms 中|
|`PLAYING_SERVER`|在第三方服务器中|
|`PLAYING_HOSTED_SERVER`|在自己托管的服务器中|
|`OFFLINE`|离线|

### PresenceResponse

```javascript
{
	"presence":[ /* PresenceDto 数组 */ ]
}
```

`presence` 允许为 `null`，客户端会将其视为空数组。

## 好友接口

### 查询好友列表

`GET /minecraftservices/friends`

请求头（可选）：`If-None-Match: {上次响应的 ETag}`

响应格式（`FriendsListResponse`）：

```javascript
{
	"friends":[
		{ "profileId":"069a79f4-44e9-4726-a5be-fca90e38aaf5", "name":"Notch" }
	],
	"incomingRequests":[],
	"outgoingRequests":[]
}
```

响应头：

|头部|说明|
|----|----|
|`ETag`|**（建议）** 资源版本标识，供客户端条件请求使用|
|`Retry-After`|**（建议）** 下次轮询的间隔秒数|

若 `If-None-Match` 与当前 `ETag` 匹配，服务端应返回 `304 Not Modified`。

### 发送好友操作

`PUT /minecraftservices/friends`

客户端的所有好友关系变更（添加、删除、接受、拒绝、撤回）都通过这一个接口完成。

请求格式：

```javascript
{
	"name":"对方的角色名称（按名称操作时提供，否则为 null）",
	"profileId":"对方的角色 UUID（带连字符；按 UUID 操作时提供，否则为 null）",
	"updateType":"ADD 或 REMOVE"
}
```

`name` 与 `profileId` 二者有且仅有一个非空。

`updateType` 的语义（由客户端各方法映射而来）：

|`updateType`|标识字段|语义|
|-------------|--------|----|
|`ADD`|`name`|按名称发送好友请求|
|`ADD`|`profileId`|接受收到的好友请求；或按 UUID 发送好友请求|
|`REMOVE`|`profileId`|删除好友、拒绝收到的请求、或撤回发出的请求|

响应格式：同 `FriendsListResponse`。操作成功后，服务端应在响应中返回**变更后的完整好友列表**。

### 上报在线状态

`POST /minecraftservices/presence`

客户端在进入/退出游戏世界时上报自己的状态，并同时获取好友的在线状态。

请求头（可选）：`If-None-Match: {上次响应的 ETag}`

请求格式：

```javascript
{
	"status":"上报的状态（PresenceStatus 枚举值，如 ONLINE、OFFLINE）"
}
```

响应格式（`PresenceResponse`）：

```javascript
{
	"presence":[
		{ "profileId":"069a79f4-44e9-4726-a5be-fca90e38aaf5", "pmid":"069a79f4-44e9-4726-a5be-fca90e38aaf5", "status":"ONLINE", "lastUpdated":"2026-01-01T00:00:00Z" }
	]
}
```

响应头：同 [§查询好友列表](#查询好友列表)，可含 `ETag` 与 `Retry-After`。

若 `If-None-Match` 匹配，返回 `304 Not Modified`（无响应体）。

## 属性接口

好友功能的入口是否显示，取决于 `GET /minecraftservices/player/attributes` 返回的 `friendsPreferences` 字段。

> 说明：在未实现本接口时，`api.minecraftservices.com/player/attributes` 会由 authlib-injector 在本地拦截并返回一个不含 `friendsPreferences` 的响应，导致好友入口不出现。本仓库已移除该本地拦截，改为转发至验证服务器，因此**服务端必须实现本接口**，否则好友入口不会显示。

### 查询玩家属性

`GET /minecraftservices/player/attributes`

响应格式：

```javascript
{
	"privileges":{
		"onlineChat":{ "enabled":true },
		"multiplayerServer":{ "enabled":true },
		"multiplayerRealms":{ "enabled":true },
		"telemetry":{ "enabled":false }
	},
	"friendsPreferences":{
		"friends":"ENABLED",
		"acceptInvites":"ENABLED"
	},
	"profanityFilterPreferences":{
		"profanityFilterOn":false
	}
}
```

`friendsPreferences` 的两个字段取值均为 `ToggleValue` 枚举：`ENABLED` 或 `DISABLED`。二者均为 `ENABLED` 时，好友入口显示且允许接收好友请求。

> **重要：** `privileges` 与 `profanityFilterPreferences` 等字段关系到聊天签名、玩家举报、封禁状态等其它功能。由于 authlib-injector 不再在本地为 `player/attributes` 提供兜底响应，服务端应返回**完整且合理**的属性，否则这些功能会退化。

### 更新玩家属性

`POST /minecraftservices/player/attributes`

客户端在用户于好友设置界面切换「允许好友」「允许好友请求」时调用。

请求格式：

```javascript
{
	"friendsPreferences":{
		"friends":"ENABLED",
		"acceptInvites":"DISABLED"
	}
}
```

> 注意：本接口的 HTTP 方法是 `POST`（不是 `PUT`）。

服务端应更新对应账号的偏好设置，并返回 `200`。

## HTTP 状态码

客户端将非 2xx 响应映射为内部的 `ResultCode`。服务端应按以下约定返回状态码，否则客户端 UI 会显示错误的提示：

|HTTP 状态码|客户端 ResultCode|场景|
|-----------|------------------|----|
|`429`|`TOO_MANY_REQUESTS`|请求过于频繁，被限流|
|`500` 及以上|`SERVICE_NOT_AVAILABLE`|服务端故障，稍后重试|
|`403`|`FORBIDDEN`|账号无可用角色等|
|`400`|`UNKNOWN_PROFILE`|目标角色名称或标识不存在|
|`401`|`UNAUTHORIZED`|令牌无效|
|其它非 2xx|`ERROR`|其它错误|

## 版本兼容性

好友功能所依赖的类（`com.mojang.authlib.services.*`）**仅在 authlib 10 及以上存在**。经验证，authlib 4.0.43（Minecraft 1.16 时代）与 6.0.54 均**不含** `FriendsService` 及其相关的 `com.mojang.authlib.services` 包，其 `EnvironmentParser` 也不同（使用 `minecraft.api.auth.host`、`minecraft.api.session.host`、`minecraft.api.services.host` 等按服务分列的属性，而非 discovery 机制）。

因此：

* **旧版本客户端不会请求本文的任何接口。** 实现本文接口对旧版本客户端是「死代码」，不会产生任何请求，也不影响其登录、进服、皮肤等既有流程。
* 服务端**无需为兼容旧版本做任何特殊处理**：不必按版本分叉逻辑，不必增加开关。接口存在与否对旧版本客户端不可见。
* 唯一需要注意的是**不要因为新增这些路由而破坏既有路由**。建议将本文接口置于 `/minecraftservices/` 前缀下（本文的路径已如此设计），与 Yggdrasil 主体接口（`/authserver/`、`/sessionserver/`、`/api/`）隔离，避免路径冲突。
* 服务端可按自身实现选择对旧版本玩家直接返回 `401`（其令牌体系若与新版一致则无此需要）；由于旧版本客户端从不调用，此举通常无实际影响。

## 边界说明

* `POST /minecraftservices/presence` 仅用于同步**在线状态**。好友之间的「加入对方的世界」等玩法**不经过**本文所述的任何接口，仍走 Realms 或服务器列表链路，不在本规范范围内。
* 本文基于 Minecraft 26.3 / authlib 10.0.77 实测。跨版本时字段可能变化，建议服务端实现时对未知字段保持宽容（反序列化端亦然）。
